# File map

- `engine.js` — core: pending downloads (probe with `probe.duplicate`, `confirm()`), the run queue, dynamic segmentation, resume, retries, stall watchdog, global and per-download speed limits, duplicates (number / replace / resume), named queues and their scheduler tick (`queues()`, `startQueue()`, `stopQueue()`, retries, when done), editable categories (`settings.types`, `CATEGORIES` as the default), per-download description, when done, last try and the Download complete flag, the one power countdown (all downloads, a download, a queue), `state.json` persistence and migrations, `view()` for the native app
- `hls.js` — HLS (.m3u8): best-variant pick and its separate sound track (X), AES-128 decryption, parallel segment fetch written in order, ffmpeg join of video and sound
- `ytdlp.js` — YouTube via yt-dlp + ffmpeg: URL check, format list with real sizes (`listFormats`, cached 15 min), format key / quality → args, tool lookup, progress parsing, pause (process-tree kill), temp folder `.fastdl\<id>`
- `server.js` — the engine's local HTTP API on 127.0.0.1:9614 (JSON only, no pages); Host/Origin checks live here; extensions only get ping, add, formats and open; `open` counter in `/api/state` (tray, popup's Open); `/api/queues` (the Scheduler); `mgr.opener` (Open, and a download's "when done: open"); app presence (`confirm: true` → 503 when the native app has not polled `/api/state` for 5 s); pause all, quit; Windows integration: Start with Windows shortcut (native exe `--tray`), sleep/shutdown commands (`mgr.power`)
- `desktop.js` — the engine launcher: `brand.json` reading, `exe` (native `<name>.exe`) and `engineExe` (`<name> Engine.exe`) paths, port/URL, `powershell()`, `shortcut()`, `start()` (exits if the engine already runs, errors if another program has the port, else imports `server.js`); `node desktop.js`
- `install.js` — builds `<name> Engine.exe` (Node single executable app: launcher, brand icon, version info, no console) and the native `<name>.exe` (`app/build.js` `compileApp()`); refuses while either runs; install/uninstall of both exes and the shortcuts (to the native exe); pure PE/icon/version-info helpers for tests
- `install.cmd`, `uninstall.cmd` — double-click wrappers for `node install.js [uninstall]`
- `brand.json` — the app's name (Arrow) and icon (`assets/logo.ico`): the one place to rename or rebrand both exes (`extension.test.js` checks the extension's copies of the name)
- `app/` — the native Windows app (C# 5 WinForms, compiled by Windows' own .NET Framework `csc.exe`) that replaces the web UI
  - `Core.cs` — pure logic: JSON (JavaScriptSerializer) with typed accessors, the `/api/state` model (`State`, `Settings`, `Queue`, `Download`, `Probe`, `FormatOption`), the helpers ported from the old web UI (numbers and dates in the user's regional format), the list's columns, cells, sorting and fitting, status texts ("In <queue>"), the speed limit text, the next queue start, duplicates, Properties, category and file-type checks and request bodies, and the parser of the sidebar's SVG icons (`ParseSvg`: any path data as absolute M/L/C/Z steps, plus the fill rule; transforms or other shapes give null)
  - `Api.cs` — the engine's HTTP API (`FASTDL_PORT`, no proxy, timeouts, `ApiException` with `Offline`) and `Poller` (`/api/state` every 700 ms on a background thread)
  - `Program.cs` — entry point: one instance (a second start tells the first to show), starts `<name> Engine.exe` (or `node desktop.js`) when the engine does not answer; `--tray`, `--no-engine`, `--check`; `ARROW_SHOTS` screenshot mode; `AppIcon` (the brand .ico through user32 `LoadImage`)
  - `Theme.cs` — `docs/NATIVE_UI.md` tokens for light and dark (follows Windows, live), fonts, text drawing and measuring, `Glyph` codes and drawing (Segoe Fluent Icons), tiles, dark title bar, native control theming, menu renderer
  - `FileIcons.cs` — the icon Windows shows for a file type (SHGetFileInfo on the extension only), scaled and cached per extension and size, for list rows and the dialogs' headers; the sidebar's Types: the `assets/types/` SVG icons as cached vector paths, filled in the text color
  - `ColorText.cs` — text with emoji in color: DirectWrite layouts drawn through a cached Direct2D DC render target (COM interop), with TextRenderer's alignment, wrapping, ellipsis and GDI's line height; Theme falls back to TextRenderer on any failure
  - `Controls.cs` — reusable custom-drawn controls: `FlatButton`, `TextField`, `Picker`, `FlatCheck`, `FlatRadio`, `SegmentBar`, `Sparkline`, `Tile`, `Caption`, `FactRow`, `Strip`, `Canvas`, `Sidebar` (with headings and a running queue's dot), `DownloadList` (columns, with row accessibility), `ListHeader` (the column titles, click to sort)
  - `Inspector.cs` — the details panel (the right column, hidden by default): one download, several, or the overview; `ErrorBox`
  - `MainForm.cs` — the main window (top bar with the paste bar, command bar with Speed limit ▾, strips, sidebar with Types and Queues, search, Sort ▾ and View ▾, the list, the details panel, status bar with the speed limit chip and next queue start), the row menu (Add to queue, Move up/down, Properties), tray icon and menu, keyboard shortcuts, drag and drop, clipboard offers, `ui.json` (bounds, section, sort, columns, details panel, the progress window's disclosures), shots
  - `Dialogs.cs` — the dialogs' static API used by the main window (one Download File Info / progress window per download, fed by `Update(State)`), the themed `Dialog` base (body over footer, centering, Esc), engine calls off the UI thread, bringing Download File Info to the front, the small modal dialogs (Confirm, Remove, a one-line text prompt, Link already in the list, Error, About), the entry points of Properties and the category editor, and the dialogs' ARROW_SHOTS pictures
  - `FileInfoDialog.cs` — Download File Info for a pending download (confirm.html's behavior): format list, category (+ a new one through the category editor), Save As + Browse…, description, POST /api/confirm start / later / cancel, then the progress window; asks or applies the duplicates choice when `probe.duplicate` comes; `QueuePopover`, Download Later's Add to queue popover
  - `PropertiesDialog.cs` — Properties (row menu, details panel): header, Address (editable while stopped, not YouTube) and Description, facts, Show in folder; sends only what changed (`url`, `describe`)
  - `CategoryDialog.cs` — the category editor (Download File Info's +, Options › Categories): Name (read-only for the built-ins), File types, Folder; POST /api/settings {types, folders}
  - `SchedulerDialog.cs` — the Scheduler (command bar, a sidebar queue's menu; one window at a time): the queues (New queue, Delete), the selected queue's fields validated inline and sent at once in order (POST /api/queues update), its unfinished files (Move up, Move down, Remove from queue), Start now / Stop; refreshed by polls without overwriting a field being edited; `DayChip`, `QueueFiles`
  - `ProgressDialog.cs` — the progress window (progress.html's behavior, the details panel's look): running with the Connections and Options disclosures (this download's limit and when done), the Download complete view (Open with…, "Don't show this window again"), removed; `Disclosure`, `ConnectionTable`
  - `AddLinksDialog.cs` — Add links: batch ranges, Quality for YouTube links, Save as, Start later, POST /api/add per link
  - `OptionsDialog.cs` — Options: a page navigation (General, Downloads, Categories, Queues); General and Downloads validated inline, Save sends only what changed (POST /api/settings); Categories: `CategoryTable`, Add / Edit… through the category editor, Remove (custom ones, asks first, POST {types}); Queues: Open Scheduler (saves, closes Options, opens the Scheduler)
  - `Tests.cs` — console test of `Core.cs` with the old `ui.test.js`'s cases, the list's columns, sorting and status texts, the IDM-parity helpers, emoji detection (`HasEmoji`), file icon extensions (`IconExt`), the SVG icon parser (`ParseSvg`), plus an `/api/state` round trip
  - `build.js` — `compileApp()` (winexe with name, version, icon, manifest) and `compileTests()` through `csc.exe`
  - `app.manifest` — asInvoker, Windows 10/11, DPI-aware, visual styles
- `extension/` — MV3 extension for Chromium browsers (Brave, Chrome, Edge)
  - `manifest.json` — permissions
  - `common.js` — app URL, `appAlive()`, `send()` (adds cookies and referrer, returns the download's id), `sendConfirm()` (adds it as pending; the native app shows the Download File Info window), `pickMedia()` (what the video button downloads), `youTubeId()`, `playerData()` (runs in the YouTube page's MAIN world: its player's formats) and `optionsFromPlayer()` (those formats → the same list as ytdlp.js `formatOptions()`)
  - `background.js` — download takeover, context menu, media grabber (webRequest), badge, the video button's messages (send, and the format list: at once from YouTube's player in the page through `chrome.scripting`, else `/api/formats`, which is always asked and kept per page); each sends as pending, for the native app's Download File Info window
  - `content.js` — IDM-style download panel over page videos: Download this video, ? (help), × (hide on that video), drag to move (every frame, closed shadow root, one click sends; on YouTube it first opens the format list from `/api/formats`); a classic script
  - `icons/` — the logo for the toolbar and the extensions page (16, 32, 48, 128 px)
  - `popup.html`, `popup.js` — media found on the current tab, Download this video on YouTube pages (both through the Download File Info window), takeover and video-button switches, Open (`POST /api/open`)
- `engine.test.js` — engine tests against a local test server, including pending downloads: probe, confirm, numbering, expiry; per-download fields and limit, duplicates, the countdown, queues and their scheduler (a test clock), categories; HLS with a separate sound track, made and checked with the real ffmpeg (skipped without it)
- `extension.test.js` — extension logic (background.js, `pickMedia`, `playerData`/`optionsFromPlayer` against `formatOptions`, popup, content.js helpers) with fake `chrome` and `fetch`, plus manifest/syntax checks and its name against `brand.json`
- `ytdlp.test.js` — YouTube URLs, format list and sizes, args, progress, pause/resume, errors, using the fake yt-dlp
- `fixtures/fake-ytdlp.mjs` — stand-in for yt-dlp in tests (prints the FDL* lines, writes files, answers `-J`)
- `fixtures/ytdlp-formats.json` — `yt-dlp -J` output of a fake 19 s video, used for the format list
- `fixtures/youtube-player.json` — real captures, trimmed: `playerData()` from YouTube's page and `yt-dlp -J` of the same videos (a 4K60 HDR video; a dubbed video with 23 audio tracks, some itags only), for `optionsFromPlayer()` = `formatOptions()`
- `server.test.js` — API access rules (Host, Origin, extension privileges), routes with query strings, `/api/open` and `open`, `/api/queues` and Later into a queue, `types` through `/api/settings`, pending downloads (503 until the native app polls) and `/api/confirm`, UTF-8 bodies, the Start with Windows shortcut, Pause all and Quit, against `server.js` spawned on a free port with a temp `FASTDL_STATE` and `FASTDL_STARTUP`
- `desktop.test.js` — brand name rules, second start and port conflict (`node desktop.js` against a stand-in server)
- `install.test.js` — icon resources, version info and PE edits; a real build + install + run + uninstall in a temp folder: native `<name>.exe` and `<name> Engine.exe`, shortcuts to the native exe (Windows)
- `app.test.js` — the native app (Windows): `Tests.cs` passes, the exe builds with the brand icon, `--check` against `server.js` on a free port with temp state
- `assets/logo.svg` — app logo source: the user's paper-plane arrow (`#3B3C3D`) on a white rounded tile; `logo.png` (512 px), `logo.ico` (16–256 px) and the extension's `icons/icon-16|32|48|128.png` are rendered from it, with thicker lines at small sizes. `brand.json` points at `logo.ico`, which goes into both exes and the tray as is
- `assets/types/` — the user's SVG icons for Video, Music, Documents, Programs, Compressed and Other (paths with any commands, filled in the text color with the file's fill rule; a transform, another shape or fill="none" shows the glyph), the glyph being only the fallback for a missing or unreadable file
- `package.json` — `start` and `test` scripts; `"type": "module"`; its `version` goes into the exe's file properties
- `state.json` — runtime state and settings (gitignored, created on first run)
- `<name>.exe`, `<name> Engine.exe`, `installed.json` — made by `install.js` (gitignored)
- `README.md` — user guide: install, start, quit, uninstall, name and icon, extension install, the main window, queues and the Scheduler, speed limit, links already in the list, categories, when done, Properties, Download File Info, YouTube, features, settings, limits, privacy
- `docs/agents/` — settings for the Matt Pocock engineering skills: issue tracker (local `.scratch/`), triage labels, domain-doc rules
- `docs/SPEC.md` — behaviour, data model, API, security model
- `docs/NATIVE_UI.md` — the native app's design: tokens, fonts, icons, the main window and every dialog, with sizes
- `docs/PLAN.md` — task list and status, known gaps
- `.scratch/<feature>/` — the local issue tracker: `idm-parity/` holds the approved spec, the mockups (m1–m5) and issues 01–09
