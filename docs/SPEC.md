# FastDL spec

Personal download manager modelled on how Internet Download Manager works (from public knowledge; no reverse engineering, no license bypass).

## Non-goals
DASH audio+video merging for sites other than YouTube, DRM, torrents, FTP, site grabber, proxy settings.

## Download engine (`engine.js`)
- **Probe = first connection.** `GET` with `Range: bytes=0-`. 206 + `Content-Range` total, or 200 + `Accept-Ranges: bytes` + length → resumable. The probe's body keeps streaming as segment #1. 416 → asked again without `Range` and downloaded as not resumable (zero-byte files). 5xx and 429 are retried up to 4 times; a numeric `Retry-After` (capped at 30 s) replaces the default backoff.
- **Dynamic segmentation.** Up to `settings.connections` connections per download. A free connection first takes an unstarted/unfinished piece; otherwise it splits the largest active piece in half (only if each half keeps ≥ 512 KB). A piece shrinks under a running connection, which stops at the new end.
- **Resume.** Each retry asks for `bytes=pos-end` and must get 206 with `Content-Range` starting at `pos` and the same total; anything else is an error (file changed on the server).
- **Not resumable.** One connection; every retry, pause or restart starts over from byte 0.
- **Failures.** A connection retries up to 5 times (2 while others are alive). When it gives up while others are alive, it is retired and the download carries on with fewer connections (servers that cap connections per user). No data for `stallMs` (30 s) cuts a connection off.
- **Files.** Written into `<name>.fdl` (preallocated), renamed when complete; `segments` are then dropped from the state. Names: `Content-Disposition` → URL → `download`; `sanitize()`; duplicates get ` (n)`; optional category subfolders (Video, Music, Compressed, Documents, Programs).
- **Queue.** At most `settings.maxActive` downloads run; others wait as `queued`. `scheduled` downloads become `queued` when the clock hits `settings.scheduleAt` (daily, app must be running).
- **Speed limit.** One global debt-based token bucket across all connections.
- **State.** `state.json`: settings + list. Saved atomically every second while anything runs or changed. `downloading` loads back as `queued`.
- **Pause all** (tray). `pauseAll()` pauses `downloading` and `queued` downloads and aborts running ones without a `pump()`, so no queued download starts in between. `scheduled` downloads keep their start time.
- **When all downloads finish.** `whenDone` (`sleep` | `shutdown` | `''`) lives in memory only and is used once, so a forgotten "shut down" can't fire days later or after a restart. Work = `downloading`, `queued`, or `scheduled` while `scheduleAt` is set; paused and failed downloads don't count. On the tick after the last work ends, a `powerDelayMs` (60 s) countdown starts; a download that started and ended between two ticks still counts (`worked`). New work stops the countdown, and it starts again when that work ends. `whenDone: ''` (Cancel) stops it at once. At zero, `whenDone` goes back to `''` and `power(op)` runs. `power` does nothing in `engine.js`; `server.js` sets the real one, so tests and other users of `Manager` can't switch the PC off.

## HLS (`hls.js`)
Master playlist → highest `BANDWIDTH`. AES-128 with explicit IV or media-sequence IV; other methods are refused as DRM. `#EXT-X-BYTERANGE` playlists are refused. Segment bodies are read chunk by chunk under the stall watchdog. `#EXT-X-MAP` → `.mp4` output, else `.ts`. Segments fetched `connections` at a time, written in order; resume continues at the first unwritten segment.

## Video sites (`ytdlp.js`)
- **URLs.** `youtube.com`, `www.`/`m.`/`music.youtube.com` with `/watch?v=`, `/shorts/`, `/live/`, `/embed/`, and `youtu.be/<id>`. The 11-char ID is required; channels and playlists are refused. Stored as `https://www.youtube.com/watch?v=<id>`, kind `video`, no headers or cookies.
- **Quality → args.** `best|1080|720|480|mp3` (default `best`; anything else is refused in `add()`). Video: `-f bv*+ba/b -S res[:N],vcodec:h264,ext:mp4:m4a --merge-output-format mp4` (H.264 preferred at equal resolution). MP3: `-f ba/b -x --audio-format mp3 --audio-quality 0`. Always `--ignore-config` (a user config could add cookies or change output names), `--no-playlist`, `--match-filter !is_live`; `--limit-rate` from `speedLimitKB`, fixed per run.
- **Files.** yt-dlp writes into `<dir>\.fastdl\<id>` as `media.<ext>`. On success the file is moved to its final name (`assignName()` with the title, unique ` (n)` names, categories → Video/Music), the temp folder is removed (and `.fastdl` once empty), and Mark-of-the-Web is set.
- **Progress.** Parsed from yt-dlp's stdout/stderr lines: `FDLINFO` (format ids, expected size, title), `FDLP` (per-stream bytes; `streams` keeps `{got,size}` per format so the bar does not restart), `FDLPP` (post-processor), `FDLFILE` (final path). `phase`: `video`, `audio`, `merging` (Merger), `converting` (ExtractAudio).
- **Pause/resume.** Pause kills the whole process tree (`taskkill /T /F` on Windows, process group elsewhere: yt-dlp.exe is a launcher and ffmpeg may run). Resume re-runs yt-dlp, which continues its `.part` files.
- **Tools.** yt-dlp: `FASTDL_YTDLP`, PATH, `%LOCALAPPDATA%\Microsoft\WinGet\Links`, WinGet `Packages\yt-dlp.yt-dlp_*`. ffmpeg: `FASTDL_FFMPEG`, PATH, WinGet `Packages\yt-dlp.FFmpeg_*\ffmpeg-*\bin`. Missing tool → error with the `winget install` command.
- **Errors.** First `ERROR:` line, non-zero exit or no file → error plus the hint `winget upgrade yt-dlp.yt-dlp`. Live streams → "Live streams are not supported". Cookies are never passed to yt-dlp.

## Data model
Download: `id, url, name, title, headers{cookie,referer,user-agent}, cookieHost, kind(http|hls|video), status(queued|downloading|paused|done|error|scheduled|removed), file, tmp, size, resumable, segments[{start,end,pos}], hls{done,bytes,total}, error, added, finished`; video only: `quality, phase, got, streams{format_id:{got,size}}, tmpDir`.
Settings: `dir, connections(1–32), maxActive(1–20), speedLimitKB(0 = off), scheduleAt("HH:MM" or ""), categories(bool), clipboard(bool, off)`.
Not saved: `startup` is whether the Startup shortcut exists; `whenDone` is in memory only.

## HTTP API (`server.js`, 127.0.0.1:9614)
`GET /` (UI, every "FastDL" replaced by the brand name) · `GET /favicon.ico` (the brand logo PNG) · `GET /api/ping` · `GET /api/state` → `{settings (+ startup), downloads, whenDone, powerIn (seconds left or null), exts (CATEGORIES extensions)}` · `POST /api/add {url, name?, title?, headers?, scheduled?, quality?}` (`quality` only for YouTube links) · `POST /api/settings {..., clipboard?, startup?, whenDone?}` · `POST /api/action {id, op: pause|resume|url|remove|removeFile|folder|open, url?}` (`open` runs a finished file with its default app) · tray menu: `POST /api/open` (app window), `POST /api/pause-all`, `POST /api/quit` (answers, then saves `state.json` and exits)

## Windows integration (`server.js`)
- **Start with Windows.** `startup: true` writes `<name>.lnk` into the user's Startup folder through PowerShell (`WScript.Shell`): target `<app>\<name>.exe`, arguments `--tray`, working folder the app folder. `--tray` starts the tray icon without a window. The exe path is fixed, also when the server runs under `npm start`, so the shortcut only works after `install.cmd`. `false` deletes it. The paths go to PowerShell as environment variables, so no quoting can break the command. `FASTDL_STARTUP` replaces the Startup folder (tests).
- **Sleep / shut down.** `shutdown /s /t 0`: any other timeout implies `/f`, and without `/f` an app with unsaved work can stop the shutdown. Sleep uses `[System.Windows.Forms.Application]::SetSuspendState('Suspend', $false, $false)`, because `rundll32 powrprof.dll,SetSuspendState` hibernates on PCs that have hibernation on.

## Desktop app (`desktop.js`, `tray.ps1`, `install.js`)
- **Brand.** `brand.json` (`name`, `logo`) is the one place for the app's name and logo: exe and .ico names, version info, page title and texts (`server.js` replaces "FastDL"), favicon, tray tooltip and menu, shortcut names. `readBrand()` allows 1–40 letters, digits, spaces and `. _ ( ) + ! -`, not starting or ending with a space or a dot: the name becomes file names, HTML/JS text and PowerShell input. The browser extension is not branded.
- **Exe.** `install.js` builds `<name>.exe` as a Node single executable application from the `node.exe` that runs it, without npm tools. `--experimental-sea-config` makes the blob from a small launcher. The copy of node.exe drops its Authenticode signature (it would no longer match). kernel32 `UpdateResource` (PowerShell `Add-Type`) replaces all resources with node.exe's manifest, our version info (name, version from `package.json`), the icons and the `NODE_SEA_BLOB` RCDATA. Then the SEA fuse becomes `:1` and the PE subsystem 2 (Windows GUI), so no console window. postject would do the same resource write and fuse flip, but needs npm. The launcher imports `desktop.js` from the exe's folder, so code changes need no rebuild, and shows startup errors in a message box. Rebuild after a brand or Node change.
- **Icon.** System.Drawing scales the logo PNG (high-quality bicubic, centered, transparent padding) to 16, 20, 24, 32, 40, 48, 64 and 256 px. The images are 32-bit BMPs with a mask, not PNGs: .NET Framework's `Icon` class (the tray) draws PNG images as noise. Written as `<name>.ico` (for the tray) and as RT_ICON/RT_GROUP_ICON resources.
- **Start.** `start()` asks `GET /api/ping`. FastDL answers: open the window (not with `--tray`) and exit. Connection refused: import `server.js`, start the tray, open the window (not with `--tray`). Anything else: error "port used by another program".
- **Window.** The first of Brave (per user, then Program Files), Chrome (per user, Program Files, x86) and Edge (x86, Program Files) with `--app=URL`, else `explorer.exe URL` (default browser). Started detached, so it is outside the job object below and outlives the app. A browser can't bring an existing `--app` window to the front, so a new window tells older ones (BroadcastChannel) to close; a window opened from the command line has one history entry, so `window.close()` works.
- **Tray.** `tray.ps1` (PowerShell 5.1, WinForms `NotifyIcon`, DPI-aware): a click opens the window; the menu has Open, Pause all and Quit, which call `/api/open`, `/api/pause-all` and `/api/quit`. Quit hides the icon first. It runs hidden (`windowsHide`, CREATE_NO_WINDOW) and not detached: PowerShell needs a console, so DETACHED_PROCESS is impossible, and libuv's job object (KILL_ON_JOB_CLOSE) ends it with the app however the app exits. A kill from outside can leave the icon until the mouse passes over it.
- **Install.** `install.cmd` runs `node install.js`. It refuses while the app answers on the port (Windows can't replace a running exe), builds, writes `<name>.lnk` to the Start menu Programs folder and the Desktop (`[Environment]::GetFolderPath`, so a OneDrive desktop works), re-creates the Startup shortcut (exe `--tray`) if one existed under the old or new name, records the name in `installed.json`, refreshes the icon cache (`ie4uinit -show`) and starts the exe. If `installed.json` has another name, that install is removed first. `uninstall.cmd` removes the three shortcuts, the exe, the .ico and `installed.json`; `state.json` stays.

## Security model
- Binds 127.0.0.1 only. `Host` must be `127.0.0.1:PORT` or `localhost:PORT` (DNS rebinding).
- `Origin`, when present, must be the app's own page or a browser extension. Other websites get 403.
- Extension origins may only use `GET /api/ping` and `POST /api/add`; anything else is 403. Any installed extension can reach the app, and settings (download folder, Start with Windows, sleep/shut down) or `open` would let it plant and run files. The Startup shortcut's target is fixed; nothing from the request goes into it.
- Finished files get the Mark-of-the-Web (`:Zone.Identifier` stream, `ZoneId=3`, referrer, URL without credentials) on Windows, like browsers do, so SmartScreen and Office Protected View still apply. Write errors are ignored (FAT/exFAT).
- Cookies come from the extension, are sent only to the host they were captured for, also across redirects, and are dropped from the state once the download is done.
- Header allowlist: cookie, referer, user-agent. The default User-Agent is honest.
- File names can't leave the download folder (`sanitize()`).

## UI (`ui.html`)
Single table: name, size, progress (one bar per connection), speed + connection count, time left, status, actions (Pause/Resume/Start now, Change link, Open, Folder, Remove). Settings dialog. Drop links on the window. Desktop notification on completion. Light/dark via `prefers-color-scheme`. A quality picker appears next to the link box when it holds a YouTube link; video rows show the phase as status (Downloading video/audio, Merging, Converting to MP3).
DOM-free logic sits in `<script id="helpers">`, which `ui.test.js` runs in Node.
- **Batch links.** In the add box only (not dropped links, not the extension), each `[a-b]` range expands: zero padding is kept when either number has a leading zero, a range may count down, several ranges in one link multiply. More than 1000 links in total are refused before they are built. When a range expanded, a confirm shows the count and the first and last link before anything is added. Expanded links are added like typed ones, so YouTube links among them get the picker's quality.
- **Clipboard monitoring** (`settings.clipboard`, off). When the window gets focus, the page reads the clipboard with `navigator.clipboard.readText()`. If the text is one http(s) link whose path ends in an extension from `CATEGORIES` (`exts` in the state), it shows "Download?" with Download / Dismiss. It never adds by itself. Each copied text is offered once, and links already in the list are skipped. Turning the setting on reads the clipboard at once, so the browser's permission prompt shows up then, and a refusal is explained.
  Why on focus rather than the server polling PowerShell `Get-Clipboard`: no extra process and no polling. Every copy in other apps (passwords too) stays unread until the user comes to FastDL, and that is when the offer would be seen anyway. The cost: it needs a Chromium browser's clipboard permission, and nothing happens while the window stays in the background.
- **When all downloads finish.** A select in the footer (Do nothing / Sleep / Shut down). During the countdown, a bar at the top shows the seconds left with Cancel (`whenDone: ''`), and a desktop notification is shown once if the user allowed notifications. The seconds sit outside the `role="alert"` text, so screen readers don't repeat it every second. A video that is merging or converting still counts as downloading, so the countdown waits for it.

## Extension (`extension/`)
Takes over browser downloads when the app is running (toggle in popup), "Download with FastDL" context menu, media grabber (video/audio responses > 512 KB and HLS playlists per tab, badge count), sends cookies + referrer, never the browser UA. On a YouTube video page the popup shows a quality picker (remembered) and **Download this video**. YouTube cookies are never sent to the app.
