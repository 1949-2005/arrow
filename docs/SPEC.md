# FastDL spec

Personal download manager modelled on how Internet Download Manager works (from public knowledge; no reverse engineering, no license bypass).

## Non-goals
DASH audio+video merging for sites other than YouTube, DRM, torrents, FTP, site grabber, proxy settings.

## Download File Info flow (IDM's confirm window)
- **Entry points.** Every Download click in the browser: the extension's video button, browser-download takeover, "Download with Arrow" context menu, and the popup's Download this video and media-list buttons. They call `sendConfirm()` (`common.js`), which sends `POST /api/add` with `confirm: true`. The app answers `{id}` at once with the download in status `pending`, and starts a quick probe. It then opens `/confirm?id=` with `chrome.windows.create({type: 'popup', width: 560, height: 470, focused: true})`, centred on the last focused browser window. If the app refuses a taken-over download, the browser gets it back.
- **Pending.** `pump()` never starts it; `ui.html` hides it from the list, sidebar counts and toolbar. It is never saved (`state.json` leaves it out), `load()` drops any, and `tick()` drops those older than `pendingMs` (30 min), so a window closed with its X leaves nothing behind.
- **Probe** (`probe()`, fills `d.probe = {name, category, size, type, error}`). http: `GET` with `Range: bytes=0-0` through `Manager.get()` (cookies stay on their host, 15 s limit), body cancelled; name from Content-Disposition, else the final URL; size from the Content-Range total, else Content-Length; the MIME type. A failure keeps the URL's name and the error, which the window shows as an amber note. HLS: the URL's name; `parsePlaylist()` (15 s limit) makes it `.mp4` for `#EXT-X-MAP` or a separate sound track, else `.ts`; a failure keeps `.ts` and the error. Video: first `listing: true` with the tab title (without a leading "(3) " and a trailing " - YouTube") as the name, then `formats()`: the real title (also kept as `d.title`) plus the extension of the picked key (`extOf()`), `options`, `format` (the preset key if the list offers it, else mp3 for quality mp3, else the first MP4, else the first option) and its size; a list error keeps the tab title, `options: []` and the error. The download's own name or title wins as in `assignName()`. Category from the extension (engine `CATEGORIES`, else Other).
- **Window** (`confirm.html`). URL (selectable), amber note, Format (YouTube: optgroups MP4 / WEBM / Audio, each option with its real size; "Getting formats…" while listing, when only Cancel works; "MP4 · best quality" / "MP3 · audio" (legacy `best`/`mp3`) when the list failed), Category, Save As with Browse…, Size (the format's size; "Known once the download starts" for YouTube without one, "Unknown" without a size). Save As starts as `<dir>\<Category>\<name>`; Category rewrites the folder (`<dir>` itself for Other or when `settings.categories` is off, as `assignName()` does); Format swaps the extension (`.mp4/.webm/.m4a/.mp3`), Video/Music (m4a and mp3 are Music) and the size. Start sends `format` (a listed key) or `quality` (legacy). Start Download (Enter) → `/progress?id=` in the same window (`location.replace`, so `window.close()` still works); Download Later and Cancel (Esc) close it. Server errors show under Save As.
- **`confirm(id, {action, path, quality, format})`** (async). Only for a `pending` download. `cancel` removes it. `start` → `queued`, `later` → `paused`. `path` must be a full Windows path (drive or `\\server\share`) ending in a file name; the name goes through `sanitize()`, video gets `extOf(format, quality)`; `format` must match `FORMAT_KEY` and be in the video's list (fetched again when the cache expired), else "unknown format"; a legacy `quality` clears `format`; the folder is created, and a taken name (file, `.fdl`, or another download's) gets ` (n)`. Sets `file`, `name`, `tmp`; `assignName()` keeps a preset `file`, so http, HLS and video all write there.
- **Browse…** `POST /api/browse {path}` runs `mgr.browse(path)`. `server.js` sets it to Windows' `SaveFileDialog` through PowerShell: owned by a hidden TopMost form so it shows in front, `InitialDirectory`/`FileName` from the path, no overwrite prompt (names get numbered instead), UTF-8 output, values in environment variables. `{path}` or `{path: null}` on Cancel. `FASTDL_BROWSE_STUB` (a folder) replaces it in tests, because the real dialog opens on the screen.
- **Progress window** (`progress.html`). Polls `/api/state` every 700 ms. Header "Downloading · 45%" / "Paused · 45%" / "Queued" / "Merging" / "Error"; title `45% · <name>`; rows URL, Status, File size, Downloaded, Transfer rate, Time left, Resume capability; a progress bar and the Connections bar (one piece per connection for http, one fill for HLS and video); Pause/Resume and Cancel (confirm, then `remove`, then close). Done: "Download complete" with Saved to, File size, URL, a full green bar, Open folder / Close / Open. Removed elsewhere: "This download was removed." and Close. Status changes go to a polite live region. `ui.html` opens it with a double-click on an unfinished row (`window.open(..., 'arrow-progress-' + id, 'popup,width=560,height=470')`).

## Download engine (`engine.js`)
- **Probe = first connection.** `GET` with `Range: bytes=0-`. 206 + `Content-Range` total, or 200 + `Accept-Ranges: bytes` + length → resumable. The probe's body keeps streaming as segment #1. 416 → asked again without `Range` and downloaded as not resumable (zero-byte files). 5xx and 429 are retried up to 4 times; a numeric `Retry-After` (capped at 30 s) replaces the default backoff.
- **Dynamic segmentation.** Up to `settings.connections` connections per download. A free connection first takes an unstarted/unfinished piece; otherwise it splits the largest active piece in half (only if each half keeps ≥ 512 KB). A piece shrinks under a running connection, which stops at the new end.
- **Resume.** Each retry asks for `bytes=pos-end` and must get 206 with `Content-Range` starting at `pos` and the same total; anything else is an error (file changed on the server).
- **Not resumable.** One connection; every retry, pause or restart starts over from byte 0.
- **Failures.** A connection retries up to 5 times (2 while others are alive). When it gives up while others are alive, it is retired and the download carries on with fewer connections (servers that cap connections per user). No data for `stallMs` (30 s) cuts a connection off.
- **Files.** Written into `<name>.fdl` (preallocated), renamed when complete; `segments` are then dropped from the state. Names: `Content-Disposition` → URL → `download`; `sanitize()`; duplicates get ` (n)`; optional category subfolders (Video, Music, Compressed, Documents, Programs).
- **Queue.** At most `settings.maxActive` downloads run; others wait as `queued`. `scheduled` downloads become `queued` when the clock hits `settings.scheduleAt` (daily, app must be running).
- **Speed limit.** One global debt-based token bucket across all connections.
- **State.** `state.json`: settings + list. Saved atomically every second while anything runs or changed. `downloading` loads back as `queued`.
- **Pause all** (tray). `pauseAll()` pauses `downloading` and `queued` downloads and aborts running ones without a `pump()`, so no queued download starts in between. `scheduled` downloads keep their start time.
- **When all downloads finish.** `whenDone` (`sleep` | `shutdown` | `''`) lives in memory only and is used once, so a forgotten "shut down" can't fire days later or after a restart. Work = `downloading`, `queued`, or `scheduled` while `scheduleAt` is set; paused and failed downloads don't count. On the tick after the last work ends, a `powerDelayMs` (60 s) countdown starts; a download that started and ended between two ticks still counts (`worked`). New work stops the countdown, and it starts again when that work ends. `whenDone: ''` (Cancel) stops it at once. At zero, `whenDone` goes back to `''` and `power(op)` runs. `power` does nothing in `engine.js`; `server.js` sets the real one, so tests and other users of `Manager` can't switch the PC off.

## HLS (`hls.js`)
Master playlist → highest `BANDWIDTH`. **Separate sound** (X serves video and sound apart): when that variant's `AUDIO` group has `#EXT-X-MEDIA:TYPE=AUDIO` tracks with a `URI`, the group's `DEFAULT=YES` track (else its first) is downloaded too; a track without a `URI` is inside the video already. AES-128 with explicit IV or media-sequence IV; other methods are refused as DRM. `#EXT-X-BYTERANGE` playlists are refused. Segment bodies are read chunk by chunk under the stall watchdog. `#EXT-X-MAP` or a separate sound track → `.mp4` output, else `.ts`. Segments fetched `connections` at a time, written in order, one track after the other: video into `d.tmp`, sound into `<file>.audio.fdl`. `d.hls = {done, bytes, total, parts: [{done, bytes}]}`: totals over both tracks for the UI, `parts` per track; resume continues at each track's first unwritten segment (older state without `parts` starts over). Then ffmpeg (`ffmpegExe()`, looked up before anything downloads, so a missing ffmpeg fails at once with the winget hint) copies both into `<file>.join.fdl` (`-map 0:v:0 -map 1:a:0 -c copy`, `-f mpegts` for a `.ts` name, else `mp4`) with `phase: 'merging'`; that file becomes `d.file` and the temp files are deleted (`remove` deletes them too). A pause during the join kills ffmpeg and waits for it to exit; resume joins again.

## Video sites (`ytdlp.js`)
- **URLs.** `youtube.com`, `www.`/`m.`/`music.youtube.com` with `/watch?v=`, `/shorts/`, `/live/`, `/embed/`, and `youtu.be/<id>`. The 11-char ID is required; channels and playlists are refused. Stored as `https://www.youtube.com/watch?v=<id>`, kind `video`, no headers or cookies.
- **Format list** (`listFormats()`, `formatOptions()`). `yt-dlp -J --no-playlist --ignore-config --no-warnings` (2 min limit), cached 15 min per video id in `mgr.formatCache` (callers during a run share it; a failure is not cached). Live → refused. Options `{key, group: MP4|WEBM|Audio, label, tag?, size}`: https formats only; video-only SDR mp4/webm of at least 144p (the short side, so shorts say 1080p), one per height, best first, H.264 preferred in MP4; paired with the best m4a (MP4) or webm/opus (WEBM) audio; label `720p`/`1080p60`, tag HD (720–1080), 2K (1440), 4K (2160). Audio: M4A (best m4a) and MP3. **Sizes are real:** yt-dlp's `filesize`, else `exactSize()` (a `Range: bytes=0-0` request with the format's own headers, no cookies, 15 s, the Content-Range total of a 206); a format with neither is left out; MP4/WEBM = video + audio; MP3 = duration × 192 kbps / 8 (constant bitrate). Measured on a 19 s video: MP4 144p shown 504,566 B, file 506,017 B; MP3 shown 456,000 B, file 457,388 B (merging and the MP3 header).
- **Format → args** (`formatArgs()`). Keys (`FORMAT_KEY`): `mp4:<v>+<a>`, `webm:<v>+<a>` → `-f <v>+<a> --merge-output-format mp4|webm`; `m4a:<a>` → `-f <a>`; `mp3` → `-f ba/b -x --audio-format mp3 --audio-quality 192K`. A key is checked against `FORMAT_KEY` in `add()`, `confirm()` and `formatArgs()`, and against the video's list in `confirm()` and before yt-dlp starts ("This video no longer offers the format …"). Legacy `quality` `best|1080|720|480|mp3` (default `best`; anything else is refused in `add()`), used when there is no `format`: video `-f bv*+ba/b -S res[:N],vcodec:h264,ext:mp4:m4a --merge-output-format mp4` (H.264 preferred at equal resolution); mp3 as above. Always `--ignore-config` (a user config could add cookies or change output names), `--no-playlist`, `--match-filter !is_live`; `--limit-rate` from `speedLimitKB`, fixed per run.
- **Files.** yt-dlp writes into `<dir>\.fastdl\<id>` as `media.<ext>`. On success the file is moved to its final name (`assignName()` with the title, unique ` (n)` names, categories → Video/Music), the temp folder is removed (and `.fastdl` once empty), and Mark-of-the-Web is set.
- **Progress.** Parsed from yt-dlp's stdout/stderr lines: `FDLINFO` (format ids, expected size, title), `FDLP` (per-stream bytes; `streams` keeps `{got,size}` per format so the bar does not restart), `FDLPP` (post-processor), `FDLFILE` (final path). `phase`: `video`, `audio`, `merging` (Merger), `converting` (ExtractAudio).
- **Pause/resume.** Pause kills the whole process tree (`taskkill /T /F` on Windows, process group elsewhere: yt-dlp.exe is a launcher and ffmpeg may run). Resume re-runs yt-dlp, which continues its `.part` files.
- **Tools.** yt-dlp: `FASTDL_YTDLP`, PATH, `%LOCALAPPDATA%\Microsoft\WinGet\Links`, WinGet `Packages\yt-dlp.yt-dlp_*`. ffmpeg: `FASTDL_FFMPEG`, PATH, WinGet `Packages\yt-dlp.FFmpeg_*\ffmpeg-*\bin`. Missing tool → error with the `winget install` command.
- **Errors.** First `ERROR:` line, non-zero exit or no file → error plus the hint `winget upgrade yt-dlp.yt-dlp`. Live streams → "Live streams are not supported". Cookies are never passed to yt-dlp.

## Data model
Download: `id, url, name, title, headers{cookie,referer,user-agent}, cookieHost, kind(http|hls|video), status(pending|queued|downloading|paused|done|error|scheduled|removed), file, tmp, size, resumable, segments[{start,end,pos}], hls{done,bytes,total,parts[{done,bytes}]}, error, added, finished, probe (pending only)`; video only: `quality, format, phase, got, streams{format_id:{got,size}}, tmpDir`; HLS: `phase` (`merging`) while ffmpeg joins a separate sound track.
Settings: `dir, connections(1–32), maxActive(1–20), speedLimitKB(0 = off), scheduleAt("HH:MM" or ""), categories(bool), clipboard(bool, off)`.
Not saved: `startup` is whether the Startup shortcut exists; `whenDone` is in memory only.

## HTTP API (`server.js`, 127.0.0.1:9614)
Routes match the path without the query string. `GET /` (UI), `GET /confirm?id=` and `GET /progress?id=` (every "FastDL" replaced by the brand name) · `GET /favicon.ico` (the brand .ico) · `GET /api/ping` · `GET /api/state` → `{settings (+ startup), downloads, whenDone, powerIn (seconds left or null), exts (CATEGORIES extensions), categories (CATEGORIES)}` · `POST /api/add {url, name?, title?, headers?, scheduled?, quality?, format?, confirm?}` (`quality`/`format` only for YouTube links; `confirm` adds it as `pending`) · `POST /api/formats {url}` → `{title, options}` (YouTube single-video links; cached 15 min) · `POST /api/confirm {id, action: start|later|cancel, path?, quality?, format?}` · `POST /api/browse {path}` → `{path}` or `{path: null}` · `POST /api/settings {..., clipboard?, startup?, whenDone?}` · `POST /api/action {id, op: pause|resume|url|remove|removeFile|folder|open, url?}` (`open` runs a finished file with its default app) · tray menu: `POST /api/open` (app window), `POST /api/pause-all`, `POST /api/quit` (answers, then saves `state.json` and exits)

## Windows integration (`server.js`)
- **Start with Windows.** `startup: true` writes `<name>.lnk` into the user's Startup folder through PowerShell (`WScript.Shell`): target `<app>\<name>.exe`, arguments `--tray`, working folder the app folder. `--tray` starts the tray icon without a window. The exe path is fixed, also when the server runs under `npm start`, so the shortcut only works after `install.cmd`. `false` deletes it. The paths go to PowerShell as environment variables, so no quoting can break the command. `FASTDL_STARTUP` replaces the Startup folder (tests).
- **Sleep / shut down.** `shutdown /s /t 0`: any other timeout implies `/f`, and without `/f` an app with unsaved work can stop the shutdown. Sleep uses `[System.Windows.Forms.Application]::SetSuspendState('Suspend', $false, $false)`, because `rundll32 powrprof.dll,SetSuspendState` hibernates on PCs that have hibernation on.

## Desktop app (`desktop.js`, `tray.ps1`, `install.js`)
- **Brand.** `brand.json` (`name` "Arrow", `icon` "assets/logo.ico") is the one place for the app's name and icon: exe name, version info, page title and texts (`server.js` replaces "FastDL"), favicon, tray tooltip and menu, shortcut names. `readBrand()` allows 1–40 letters, digits, spaces and `. _ ( ) + ! -`, not starting or ending with a space or a dot: the name becomes file names, HTML/JS text and PowerShell input. The extension can't read `brand.json`: its manifest name, popup and context menu hold the name, and `extension.test.js` checks they match. Internal names stay FastDL (User-Agent, `FASTDL_*` variables, ping's `app: 'fastdl'`).
- **Exe.** `install.js` builds `<name>.exe` as a Node single executable application from the `node.exe` that runs it, without npm tools. `--experimental-sea-config` makes the blob from a small launcher. The copy of node.exe drops its Authenticode signature (it would no longer match). kernel32 `UpdateResource` (PowerShell `Add-Type`) replaces all resources with node.exe's manifest, our version info (name, version from `package.json`), the icons and the `NODE_SEA_BLOB` RCDATA. Then the SEA fuse becomes `:1` and the PE subsystem 2 (Windows GUI), so no console window. postject would do the same resource write and fuse flip, but needs npm. The launcher imports `desktop.js` from the exe's folder, so code changes need no rebuild, and shows startup errors in a message box. Rebuild after a brand or Node change.
- **Icon.** The .ico goes into the exe as is: each image becomes an RT_ICON resource and the directory an RT_GROUP_ICON (`iconResources()`). Its images are PNGs, which Windows reads. The tray loads the same file with user32 `LoadImage` (LR_LOADFROMFILE) at the small-icon size, because .NET Framework's `Icon` class draws PNG images as noise.
- **Start.** `start()` asks `GET /api/ping`. FastDL answers: open the window (not with `--tray`) and exit. Connection refused: import `server.js`, start the tray, open the window (not with `--tray`). Anything else: error "port used by another program".
- **Window.** The first of Brave (per user, then Program Files), Chrome (per user, Program Files, x86) and Edge (x86, Program Files) with `--app=URL`, else `explorer.exe URL` (default browser). Started detached, so it is outside the job object below and outlives the app. A browser can't bring an existing `--app` window to the front, so a new window tells older ones (BroadcastChannel) to close; a window opened from the command line has one history entry, so `window.close()` works.
- **Tray.** `tray.ps1` (PowerShell 5.1, WinForms `NotifyIcon`, DPI-aware): a click opens the window; the menu has Open, Pause all and Quit, which call `/api/open`, `/api/pause-all` and `/api/quit`. Quit hides the icon first. It runs hidden (`windowsHide`, CREATE_NO_WINDOW) and not detached: PowerShell needs a console, so DETACHED_PROCESS is impossible, and libuv's job object (KILL_ON_JOB_CLOSE) ends it with the app however the app exits. A kill from outside can leave the icon until the mouse passes over it.
- **Install.** `install.cmd` runs `node install.js`. It refuses while the app answers on the port (Windows can't replace a running exe), builds, writes `<name>.lnk` to the Start menu Programs folder and the Desktop (`[Environment]::GetFolderPath`, so a OneDrive desktop works), re-creates the Startup shortcut (exe `--tray`) if one existed under the old or new name, records the name in `installed.json`, refreshes the icon cache (`ie4uinit -show`) and starts the exe. If `installed.json` has another name, that install is removed first. `uninstall.cmd` removes the three shortcuts, the exe and `installed.json`; `state.json` stays.

## Security model
- Binds 127.0.0.1 only. `Host` must be `127.0.0.1:PORT` or `localhost:PORT` (DNS rebinding).
- `Origin`, when present, must be the app's own page or a browser extension. Other websites get 403.
- Extension origins may only use `GET /api/ping`, `POST /api/add` and `POST /api/formats` (it only reads a YouTube video's list; keys are validated before yt-dlp sees them); anything else is 403, including `/api/confirm` and `/api/browse`: only the app's own Download File Info window picks the folder. Any installed extension can reach the app, and settings (download folder, Start with Windows, sleep/shut down) or `open` would let it plant and run files. The Startup shortcut's target is fixed; nothing from the request goes into it.
- Finished files get the Mark-of-the-Web (`:Zone.Identifier` stream, `ZoneId=3`, referrer, URL without credentials) on Windows, like browsers do, so SmartScreen and Office Protected View still apply. Write errors are ignored (FAT/exFAT).
- Cookies come from the extension, are sent only to the host they were captured for, also across redirects, and are dropped from the state once the download is done.
- Header allowlist: cookie, referer, user-agent. The default User-Agent is honest.
- File names can't leave the download folder (`sanitize()`).

## UI (`ui.html`)
IDM-style window: toolbar (Add URL, Resume, Stop, Stop all | Delete, Delete completed | Options, Scheduler; each disabled when it does not apply), categories sidebar beside the list, details pane, status bar. Toolbar actions work on the selected rows: Resume (`resume`) and Stop (`pause`) on each selected row they apply to, Stop all = `POST /api/pause-all`, Delete (also the Delete key) confirms, asks about the files when any selected download is complete and sends `removeFile` for those (else `remove`), Delete completed removes every finished download and keeps the files. Options opens the settings dialog; Scheduler opens it focused on "Start scheduled downloads at". Add URL opens a dialog: Links (several, batch ranges), a quality picker shown only while a YouTube link is in it, Save as (single link only), Start later (scheduled). Sidebar: categories from the file extension (`state.categories` = engine.js `CATEGORIES`, else Other; YouTube is Video, or Music for M4A and MP3; HLS is Video) and status (Unfinished = not done, Finished, Scheduled), each with a count; the filter is kept in localStorage and hidden rows leave the selection. Below 820 px the sidebar and Date added are hidden and the filter is not applied; below 640 px Transfer rate is hidden too. List: File name (category icon), Size, Status (mini bar + percent, Paused · %, video phase, Queued, Scheduled, Complete, Error with the full error as title), Time left, Transfer rate, Date added (Today HH:MM, Yesterday, short date; from `added`). Rows update in place by id. Selection like a file list: click, Ctrl+click, Shift+click; Up/Down, Shift+Up/Down, Ctrl+Up/Down (move only), Space, Home/End, Ctrl+A (visible rows); Enter or double-click opens a finished file; a double-click on an unfinished one opens its progress window. `pending` downloads are left out everywhere. The table is an ARIA grid (`aria-multiselectable`, `aria-selected` on rows) with one row in the tab order. Details pane: one download = name, link, folder, Downloaded x of y, Transfer rate, Time left, Connections, Resume (Yes/No/—), one bar piece per connection (HLS, video and finished ones get one fill), Open / Show in folder / Change link; several = count and total size; none = a hint. Empty list: a message with an Add URL button. Drop links on the window. Desktop notification on completion. Light/dark via `prefers-color-scheme`.
DOM-free logic (batch links, clipboard link check, category, date label) sits in `<script id="helpers">`, which `ui.test.js` runs in Node.
- **Batch links.** In the Add URL dialog only (not dropped links, not the extension), each `[a-b]` range expands: zero padding is kept when either number has a leading zero, a range may count down, several ranges in one link multiply. More than 1000 links in total are refused before they are built. When a range expanded, a confirm shows the count and the first and last link before anything is added. Expanded links are added like typed ones, so YouTube links among them get the picker's quality.
- **Clipboard monitoring** (`settings.clipboard`, off). When the window gets focus, the page reads the clipboard with `navigator.clipboard.readText()`. If the text is one http(s) link whose path ends in an extension from `CATEGORIES` (`exts` in the state), it shows "Download?" with Download / Dismiss. It never adds by itself. Each copied text is offered once, and links already in the list are skipped. Turning the setting on reads the clipboard at once, so the browser's permission prompt shows up then, and a refusal is explained.
  Why on focus rather than the server polling PowerShell `Get-Clipboard`: no extra process and no polling. Every copy in other apps (passwords too) stays unread until the user comes to FastDL, and that is when the offer would be seen anyway. The cost: it needs a Chromium browser's clipboard permission, and nothing happens while the window stays in the background.
- **When all downloads finish.** A select in the footer (Do nothing / Sleep / Shut down). During the countdown, a bar at the top shows the seconds left with Cancel (`whenDone: ''`), and a desktop notification is shown once if the user allowed notifications. The seconds sit outside the `role="alert"` text, so screen readers don't repeat it every second. A video that is merging or converting still counts as downloading, so the countdown waits for it.

## Extension (`extension/`)
Takes over browser downloads when the app is running (toggle in popup), "Download with Arrow" context menu (both open the Download File Info window), media grabber (video/audio responses > 512 KB and HLS playlists per tab, badge count), sends cookies + referrer, never the browser UA. On a YouTube video page the popup shows **Download this video** (the format is picked in the Download File Info window). YouTube cookies are never sent to the app.
- **Video panel** (`content.js`, in every frame, so embedded players work too), IDM's download panel. Hovering a rendered `<video>` of at least 200x112 px shows a panel 8 px inside its top-right corner: a grip, **Download this video** (the Arrow logo, a paper-plane arrow, as inline SVG), **?** and **×**. It hides 1.5 s after the pointer leaves the video and the panel, and follows scroll and resize. The pointer is matched by position, because players put their controls over the `<video>`. It sits in a closed shadow root on a fixed host (z-index 2147483647), so page CSS and scripts can't reach it, and only trusted clicks (mouse or keyboard) count. Not shown over fullscreen video: only the fullscreen element is drawn there. **?** opens a help box under it (how to turn it off in the popup, how to move it); OK, Esc or a click elsewhere closes it. **×** hides it at once on that video until the page's URL changes (`dismissed`: video → URL, because YouTube reuses one `<video>`). **Drag:** a trusted press that moves 4 px moves the panel (the pointer is captured only then, so a short press still clicks the button under it); the offset holds for the page; `panelAt()` keeps the panel in the window; a double-click on its edge (grip or padding) puts it back. One trusted click on **Download this video** sends. On YouTube pages (`isYouTubePage()`, same as `isYouTubeVideo()`) the button has a chevron and the click opens a format menu under the panel instead: "Getting formats…", then groups VIDEO · MP4 / VIDEO · WEBM / AUDIO with label, tag and real size; on an error, the message and "Download anyway" (no format). Up/Down wrap, Esc closes, a click elsewhere closes; the page's keys don't see the menu's keys. The menu asks `background.js` `{type: 'formats', pageUrl}`, which calls `POST /api/formats` (one request per page while the worker lives; failures asked again). A pick sends the page URL and title kept from when the menu opened (YouTube changes pages without reloading) with `format`. The content script sends `{type: 'video', src, pageUrl, title, format?}`; `background.js` takes it only from this extension with a tab, checks every field, and `pickMedia()` (`common.js`) decides: YouTube page → the page with the quality, format and title (`format` checked against `FORMAT_KEY`); http(s) `src` → that file with the page as referrer; blob:/MSE players → the tab's first grabbed HLS playlist, else its biggest video file; nothing → "No video found yet. Play it for a few seconds, then try again." The background adds it with `confirm: true` and opens the Download File Info window. The label shows "Sending…", then for 2.5 s "Sent to Arrow ✓" or the error. The popup switch "Show download button on videos" (`overlay`, on by default) removes it from open pages at once.
